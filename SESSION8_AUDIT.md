## 4. Experimental Methodology

### 4.1 Data splits

- **Digits (cell 45):** `train_test_split(X, y, row_ids, test_size=0.20, random_state=42, stratify=y)`, followed by
  `test_size=0.25, random_state=42, stratify=y_trainval`. Recomputed independently: **1077 / 360 / 360**
  (59.93 / 20.03 / 20.03 %). All pairwise overlaps are 0, and the union equals all 1797 rows.
- **MNIST (cell 126):** the same code on `mnist_ids`. Recomputed: **42 000 / 14 000 / 14 000** (60/20/20), overlaps 0,
  union = 70 000. The recomputed indices are identical to `checkpoints/mnist_split_indices.joblib`.
- **Same subsets for all models:** verified with the `data_fingerprint` stored in every checkpoint:
  - all Digits dev models are fingerprinted on the train rows and all finals on train + val;
  - the MNIST SVM dev models are on the documented 10 000-row train subset, the MLP dev models on train, and the
    finals (SVM, MLP, CNN) on train + val;
  - the CNN uses `Subset(PooledMNIST, ids)` with the same index arrays, and cell 170 asserts that the CNN batches equal
    the classical feature matrices bit-for-bit.

### 4.2 Stratification

Both datasets use `stratify` in both steps. The maximum class-share deviation from the full data is 0.15 pp (Digits)
and 0.0043 pp (MNIST). The decision is justified in §5.3 / §5.8 (small per-class counts in 20 % subsets).

### 4.3 Leakage

**None found.**

- **StandardScaler (Digits):** it only exists inside `Pipeline`s. For every checkpoint the audit verified that
  `scaler.mean_` equals the mean of the rows the model was fitted on (`n_samples_seen_` = 1077 for dev models and 1437
  for finals) and differs from the full-data mean.
- **MNIST normalisation:** `/255` is a fixed, data-independent transform (`mnist_features`, `to_model_input`).
- **Scaling diagnostics:** §6.4 and the MNIST scaling check use the training set only.
- **Model selection:** tuning is fit on train and scored on validation (`run_tuning`, `mnist_run_tuning`).
- **CNN early stopping:** uses the validation set only (`cnn_validate` → `cnn_val_loader`).

### 4.4 Validation strategy

- **Selection metric:** validation F1 macro, defined before training (§6.5), with deterministic tie-breakers.
- **Re-selection check:** the audit re-ran the selection on the stored tuning tables with the notebook's rules and
  obtained exactly the final parameters for all 3 Digits and all 4 MNIST models.
- **Stored validation scores:** these were recomputed from the `*_best_validation` checkpoints (Digits:
  0.988939 / 0.994400 / 0.986050, identical) and from `mnist_cnn_best.pt` (0.988489, identical on CPU and GPU).

### 4.5 Test isolation

Every reference to the test set (47 lines, listed by `nb_static.py`) was classified:

- **Split creation and size / proportion reporting:** cells 45, 47, 126, 128, 134, 186. These are counts and label
  proportions only; legitimate.
- **Final evaluation:** only via `evaluate_on_test` (cell 53, refuses non-`_final` names) and `mnist_evaluate_on_test`
  (cell 132). Logs: `['knn_final','svm_final','mlp_final']` and `['mnist_knn_final','mnist_svm_final','mnist_mlp_final','mnist_cnn_final']`.
- **Post-hoc reporting of final predictions:** cells 54, 101, 104, 108, 176, 179, 180, 183; legitimate.
- **Verification cells:** 111, 189; legitimate.
- **One access outside the logged evaluator:** cell 170 reads 64 test images/labels to assert that the two input
  representations are identical. This influences no decision (**AUD-009**, LOW).

The test set is **not** used to choose `k`, weights, scaling, `C`, `gamma`, kernel, hidden layers, learning rate,
`alpha`, epoch, early stopping or CNN architecture.

### 4.6 Final retraining

- **Digits:** the final checkpoints have `n_samples = 1437` = 1077 + 360, and the scaler has `n_samples_seen_ = 1437`.
- **MNIST:** SVM and MLP finals have `n_samples = 56 000`. The KNN final is refit on 56 000 rows in cell 143 (not
  checkpointed, documented). The CNN final is retrained from scratch for `best_epoch = 8` epochs on train + val
  (`mnist_cnn_final.pt`, fingerprint verified).

### 5.2 KNN

- **Coverage:** baseline `StandardScaler + k=5` (val F1 0.9616); 72 configurations
  (`scaler ∈ {standard, none}` × `weights` × 18 values of `k`); selected `scaler=none, k=2, weights=distance`
  (val F1 0.9889, a three-way tie resolved by the pre-declared tie-breaker). Final test: 0.9861 / F1 0.9859, 5 errors,

  0.9807. Standardisation hurts, but mostly for another reason: it plausibly gives equal weight to all low-variance
  peripheral pixels.
- **`metric`/`p`:** not explored. This is acceptable (optional in the brief).

## 6. MNIST Extra Work

### 6.1 Dataset

- **Source:** `torchvision.datasets.MNIST`, a single download reused by all models; the official 60k/10k parts are
  pooled and re-split. This is stated in §13.1, together with the caveat that results are not comparable to the
  official test split.
- **Verified contents:** 70 000 × 28 × 28 uint8, values 0–255, 10 classes (6 313–7 877 per class), 784 features after
  flattening, 0 duplicates, 65 always-zero pixel positions.
- **Minor:** the NaN/inf check on uint8 data is tautological (**AUD-011**).

### 6.2 KNN scalability

- **Benchmark design:** stratified train subsets of 1k/5k/10k/20k/42k, a fixed stratified set of 2 000 validation
  queries, best of 3 repetitions, `k=5`, 784 features. The comparison is fair: same queries and same algorithm.
- **Stored results verified:** prediction time 0.055 s → 1.034 s; fit time ≤ 0.081 s; accuracy 0.879 → 0.964.
- **Plot:** built from the same `knn_bench` DataFrame (cell 137).
- **O(n_train × n_features):** used explicitly as an intuitive approximation (§13.4). The table in cell 134 computes
  the 477× per-query / 18 565× whole-test ratios.
- **Honesty:** the notebook explicitly separates the expectation ("too slow") from the observation (≈ 7–8 s on this
  hardware; `run_full_knn` decided from a 7.2 s projection against a 120 s budget). **This is honest and correct.**
- **Minor:** the Digits-vs-MNIST per-query ratio (21×) compares a cached MNIST timing with a Digits timing re-measured
  on every run (**AUD-010**). The claim that "fixed overheads dominate on Digits" is plausible but not measured
  (**AUD-012**).

### 6.3 SVM

- **Tuning on a subset:** tuning used a fixed stratified 10 000-row subset of train, scored on the full validation set.
  The reason (a measured fit-time exponent of ≈ n^2.07, with 126 s projected per configuration) and the limitation are
  both stated in the markdown (§13.5). This is a defensible methodology.
- **Grid:** RBF only, `C ∈ {1, 10}` × `gamma ∈ {scale, 0.05}`. Small and justified from the Digits results.
- **Final:** trained on 56 000 rows with 10 972 support vectors; test 0.9834 / 0.9833, 232 errors (verified).

### 6.4 MLP

- **Tuning:** baseline `(100,)` plus a two-step search (architecture, then `alpha` on the best architecture); 5
  configurations, all converged (0 warnings in the checkpoints). Selected: `(256,128)`, `alpha=1e-3` (val 0.9803).
- **Preprocessing:** `/255` only, with the decision against `StandardScaler` documented and measured (76 zero-variance
  pixels; max |z| = 205).
- **Final:** 59 epochs on 56 000 rows; test 0.9843 / 0.9841, 220 errors (verified).

### 6.5 CNN

- **Architecture:** `Conv(1→32,3,p1)–ReLU–MaxPool2 → Conv(32→64,3,p1)–ReLU–MaxPool2 → Flatten(3136) → Linear(128) → ReLU → Linear(10)`.
- **Shapes:** recomputed independently as (32,28,28) → (32,14,14) → (64,14,14) → (64,7,7) → 3136 → 128 → 10.
- **Parameters:** 421 642 analytically, equal to the counted value and to the notebook (convolutional part: 18 816).
- **Training loop (cell 170):**
  - `model.train()` in training; `model.eval()` + `torch.no_grad()` in `cnn_logits` (validation and test);
  - `optimizer.zero_grad()` before each backward pass; `CrossEntropyLoss` on raw logits, with no softmax;
  - loss accumulated as `loss.item() * len(yb)` / `seen`; labels are int64 (default collate);
  - data and model on `device`.
- **Shuffling:** the train loader uses `shuffle=True` with a seeded generator; the validation loader (`cnn_val_loader`)
  and the test loader use `shuffle=False`.
- **Early stopping:** monitors validation F1 macro only, patience 3, max 12 epochs. Best epoch 8 is also the arg-min of
  the validation loss. A checkpoint is saved on every improvement, and the reloaded best model's validation F1 is
  asserted to equal the stored value.
- **Final strategy:** "best epoch → retrain from scratch on train + val for 8 epochs" is implemented and explained in
  markdown. The best-validation checkpoint is used only for monitoring and selection. One nuance: the final run takes
  438 vs 329 batches per epoch (AUD-019, INFO).
- **Test:** 0.9885 / 0.9884, 161 errors. Recomputed on CPU **and** GPU with identical predictions.
- **Checkpoints:** load on the CPU with `map_location="cpu", weights_only=True`.

### 6.6 Results comparison

## 14. Performance and Memory

- **Measured in the stored run:** kernel peak ~1.52 GB, in the SVM phase; GPU peak 230–266 MB.
- **Measures in place:**
  - the MNIST data is kept once as uint8 (55 MB);
  - float32 features are built on demand (`mnist_features`);
  - the CNN reads uint8 batches through a `DataLoader` (no full float tensor);
  - `del` + `gc.collect()` runs after each phase, only after the results are stored (verified: `MNIST_FINAL` and
    `MNIST_BUNDLE_INFO` hold everything used later).
- **Observation:** RSS barely drops after `del` (1.13 GB after KNN and after SVM), because the allocator keeps freed
  memory. The frees mainly prevent further growth.
- **NECESSARY:** none; the notebook ran within ~1.5 GB.
- **OPTIONAL:**
  - drop the float32 full-copy NaN check (AUD-011; ~220 MB transient);
  - cache the MNIST SVM test predictions, since re-predicting costs 74–84 s on every run and is the dominant run time.
- **CPU/GPU:** `device = cuda if available else cpu`; the model and batches are moved with `.to(device)`; logits come
  back to the CPU for metrics; checkpoints load with `map_location="cpu"` (verified on CPU). The CPU path is supported
  (training ≈ 25 s/epoch measured earlier on CPU; not re-run in this audit).
